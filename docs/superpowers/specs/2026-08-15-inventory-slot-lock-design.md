# 玩家背包锁定格设计

## 目标

增加“锁定格”功能：玩家可以在配置 GUI 中锁定主背包的具体槽位。执行 `/autochest deposit` 时，被锁定的槽位完全跳过，不参与存入已有堆叠或填充容器空槽。该功能仅影响 deposit，不改变 restock 行为。

## 配置范围与交互

- 每位玩家拥有独立的锁定槽位集合。
- 锁定对象是主背包槽位 `9..35`，不是物品类型；空槽也可以被锁定。
- `/autochest config` 主菜单增加“锁定格”入口。
- 锁定格页面展示玩家当前主背包 `9..35` 的物品副本，并使用明显状态标识显示已锁定槽位。
- 点击预览格切换锁定状态，点击空格同样有效。
- 页面只允许查看和点击锁定状态，禁止取出、放入、交换或移动展示物品。
- 复用现有 GUI 的玩家 UUID、页面类型和会话 token 校验；无效会话不得修改配置。

## 数据模型与持久化

在现有 deposit 偏好模型中新增锁定槽位集合，并纳入 `OperationPreferencesSnapshot`。集合必须是不可变快照，避免任务运行期间被 GUI 修改影响。

- 合法槽位范围为 `9..35`。
- 读取 JSON 时过滤 null、重复值、非法类型和范围外槽位。
- 旧版本 JSON 缺少该字段时默认空集合，保持原有行为。
- 每次切换立即更新 `PlayerPreferencesService` 内存状态，并复用现有单线程异步 JSON 原子保存队列。
- 不新增配置文件，不向 `ItemStack` 写入 PDC 标记。

## 整理执行链路

创建 deposit 任务时从玩家偏好读取并冻结锁定槽位快照，随 `PlayerTask` 传递至执行阶段。

`DepositService` 遍历主背包槽位 `9..35` 时，先判断当前槽位是否属于锁定集合：

1. 锁定槽位直接跳过，不读取其物品作为整理来源。
2. 未锁定槽位继续执行现有的快照候选判断、已有堆叠填充和空槽填充逻辑。
3. 锁定槽位中的物品不会被扣除，也不会因其他槽位整理而改变。
4. restock 路径不读取或应用锁定槽位配置。

## 线程与安全边界

- Bukkit 玩家背包读取、GUI 渲染、点击处理和库存修改继续只在主线程执行。
- 偏好服务只暴露安全的快照和更新方法，GUI 不直接访问可变 profile 或 JSON 文件。
- 任务创建后锁定配置变化只影响后续任务，不影响已开始的 deposit 任务。
- 玩家退出、死亡、切换世界、关闭 GUI 和插件停用时复用现有会话清理机制。
- 配置更新失败时保留旧内存配置并记录明确日志，不让异常绕过库存保护流程。

## 测试与验收

自动化测试至少覆盖：

1. 锁定槽位集合只保留 `9..35`，并正确去重、归一化和生成不可变快照。
2. 旧 JSON 缺少锁定字段时读取为空集合，其他配置不受影响。
3. 设置、取消设置锁定槽位会更新 deposit 快照并持久化；restock 快照不包含或不应用该配置。
4. 锁定主背包槽位中的物品不会被存入已有堆叠或空槽。
5. 未锁定槽位仍保持原有 deposit 行为。
6. 空槽锁定在页面重绘和重启后仍保留。
7. GUI 页面禁止库存物品移动，且无效 UUID 或过期 token 不能修改锁定配置。
8. 任务创建后修改 GUI 配置不会改变已冻结任务的锁定槽位集合。

Paper `1.21.4` 人工验收：在 GUI 锁定含物品和空的主背包格，执行 `/autochest deposit`，确认锁定格完全不动、其他格正常整理；重启后锁定状态恢复；执行 restock 时确认锁定设置不产生影响。
